### Experimento Prático: Construção de Laço Agêntico e Impacto de Docstrings em Function Calling

**Contexto e Objetivo:**
Como parte das atividades práticas da disciplina de Desenvolvimento de Software Apoiado por IA (UFPA), o objetivo de hoje foi construir um agente autônomo minimalista (em menos de 100 linhas de Python) baseado no padrão *Reason-Act-Observe* (ReAct) com trava de segurança (`MAX_PASSOS`). Além de implementar a orquestração do laço agêntico via Function Calling, o experimento buscou avaliar empiricamente a sensibilidade do LLM à qualidade das descrições das ferramentas (*teste da docstring ruim*), confrontando o comportamento do modelo diante de uma especificação semântica rica versus uma descrição sabotada propositalmente.

**O que foi feito:**
1. **Definição das Tools:** Foram implementadas funções locais em Python, incluindo ferramentas sem parâmetros (`horario_brasilia`) e parametrizadas (`horario_cidade`), mapeadas dinamicamente para o esquema de chamadas do modelo.
2. **Ciclo Agêntico e Trava:** O laço de execução foi construído para alternar entre a deliberação do modelo (*Reason*), a execução de código local pelo interpretador (*Act*) e a devolução do retorno no formato `role: "tool"` (*Observe*), limitado estritamente por uma variável de passos máximos (`MAX_PASSOS = 5`).
3. **Teste da Sabotagem da Docstring:** Submeteu-se a mesma pergunta (*"Qual é o horário atual em Manaus?"*) a dois cenários experimentais: primeiro com a docstring detalhada e, em seguida, reduzindo deliberadamente a descrição da ferramenta para a string vaga `"faz uma consulta"`.

**Diferença entre os cenários:**

*   **Cenário 1: Docstring Completa e Descritiva:**
    A ferramenta forneceu uma especificação semântica precisa através da docstring em Python lida via `inspect.getdoc`, explicitando a finalidade da função e as cidades com fuso suportadas.
    ```python
    def horario_cidade(cidade: str) -> str:
        """Retorna a hora atual de uma cidade conhecida (ex: Manaus, Recife, São Paulo, Tóquio)."""
        offset = fusos.get(cidade.casefold())
        return datetime.now(timezone(timedelta(hours=offset))).strftime(f"%H:%M:%S em {cidade}")
    ```

*   **Cenário 2: Sabotagem Semântica ("Docstring Ruim"):**
    A descrição no esquema de Function Calling foi substituída pela descrição genérica e inútil `"faz uma consulta"`, ocultando o objetivo real da função enquanto preservou-se apenas o nome da função e o parâmetro `cidade`.
    ```python
    # Esquema sabotado enviado à API
    {
        "type": "function",
        "function": {
            "name": "horario_cidade",
            "description": "faz uma consulta",
            "parameters": {"type": "object", "properties": {"cidade": {"type": "string"}}, "required": ["cidade"]}
        }
    }
    ```

**Resultado e Conclusão do Experimento:**
Ambos os casos convergiram em exatamente **2 passos** (1 chamada de ferramenta + 1 resposta final formulada), escolhendo a função `horario_cidade` com o argumento `{"cidade": "Manaus"}`. O modelo conseguiu inferir a intenção e a ferramenta apropriada mesmo com a docstring sabotada porque o identificador da função (`horario_cidade`) e o nome do parâmetro (`cidade`) forneceram fortes pistas léxicas que compensaram a ausência de uma descrição detalhada. Esse achado demonstra que, embora descrições ricas sejam essenciais em catálogos amplos e ambíguos de ferramentas, a nomenclatura de identificadores (*clean code* nas assinaturas de API) atua como um forte atalho semântico para LLMs de última geração durante a etapa de raciocínio.
