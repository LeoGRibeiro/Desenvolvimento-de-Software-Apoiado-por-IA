## 1. Objetivo da Tarefa

Conforme os requisitos da Aula 6 (*"Model Context Protocol: dando ferramentas ao agente"*), o objetivo foi desenvolver e integrar um servidor MCP próprio ao projeto da AP1 (**Reservei**), permitindo que um agente autônomo de IA opere o sistema real por meio de ferramentas estruturadas (*tools*).

### Critérios Atendidos:
1. **Comunicação com a Aplicação Real:** O servidor conecta-se à base de dados do Reservei (Supabase) com fallback resiliente em memória, manipulando a entidade central de reservas esportivas.
2. **Mínimo de 3 Tools (Leitura e Escrita):** Implementadas 3 ferramentas com docstrings explicativas e tipagem estrita para instruir o modelo quando utilizá-las.
3. **Configuração `.mcp.json` com Políticas de Acesso:** Políticas `allow` para ferramentas puramente de consulta e `ask` para ferramentas que realizam mutação de estado.
4. **Resolução de Tarefa Real pelo Agente:** Teste do fluxo completo via agente de IA, com gravação das conversas e análise de erros, escolhas de tools e superfície de risco da *Tríade Letal*.

## 2. Implementação do Servidor MCP (`mcp_server/`)

O servidor foi construído em Python utilizando a biblioteca **FastMCP**, operando sobre `stdio` e protocolo padrão **JSON-RPC**.

### Estrutura de Ferramentas Implementadas

| Ferramenta | Tipo | Permissão (`.mcp.json`) | Descrição e Regras |
| :--- | :---: | :---: | :--- |
| `consultar_disponibilidade` | Leitura | `allow` | Consulta a grade de horários (08:00 às 22:00) das quadras (`q1`, `q2`, `q3`) em uma data (`AAAA-MM-DD`). Retorna slots livres e ocupados. |
| `buscar_reservas_cliente` | Leitura | `allow` | Busca reservas ativas e histórico através do número de telefone/WhatsApp normalizado (com ou sem DDD). |
| `criar_reserva` | Escrita | `ask` | Registra nova reserva no Supabase. Possui validação rigorosa de slots de 1h, prevenção ativa contra *double booking* e exige confirmação humana explícita. |

### Configuração do Agente (`.mcp.json`)

```json
{
  "mcpServers": {
    "reservei": {
      "command": "python",
      "args": [
        "mcp_server/server.py"
      ],
      "env": {
        "PYTHONUNBUFFERED": "1",
        "PYTHONIOENCODING": "utf-8"
      }
    }
  },
  "permissions": {
    "reservei": {
      "consultar_disponibilidade": "allow",
      "buscar_reservas_cliente": "allow",
      "criar_reserva": "ask"
    }
  }
}
```

## 3. Resultados dos Testes Práticos (Conversas Gravadas)

Os testes foram executados com o agente de IA e registrados na pasta `conversas/`.

### Teste 1: Consulta de Disponibilidade e Criação de Reserva (`conversas/1.jsonl`)

1. **Solicitação do Usuário:**  
   *"queria saber se tem horario na quadra 2 as 20:00 do dia 14/10"*
2. **Escolha das Ferramentas pelo Agente:**  
   - O agente inspecionou as ferramentas do servidor `reservei`.
   - Chamou `consultar_disponibilidade(data="2026-10-14", quadra_id="q2")`.
   - Constatou que às 20:00 a Quadra 2 estava **ocupada** (*"Campeões Voleibol"*).
   - Proativamente, executou uma segunda consulta ampla para 14/10 e sugeriu alternativas ao usuário: Quadras 1 e 3 às 20:00 ou Quadra 2 às 18:00.
3. **Solicitação de Agendamento:**  
   *"então faça uma reserva de 17:00 as 19:00 na quadra 2 do dia 14"*
4. **Onde o Agente Errou ou Tropeçou:**  
   - **Tentativa de leitura de arquivo inexistente:** O agente tentou ler `instructions.md` dentro do diretório de schemas do MCP (`C:\Users\...\mcp\reservei\instructions.md`), recebendo erro de sistema de arquivos. Contudo, recuperou-se sem interromper a execução.
   - **Necessidade de decomposição de slots:** A ferramenta `criar_reserva` aloca slots unitários de 1 hora. O agente identificou corretamente a necessidade de realizar duas chamadas (17:00 e 18:00) para cobrir o intervalo de 2 horas.
   - **Validação de dados do cliente:** Antes de disparar a ferramenta de escrita, o agente percebeu que faltavam os dados obrigatórios do cliente (nome, WhatsApp, modalidade) e questionou o usuário antes de prosseguir.
5. **Execução da Escrita (`ask`):**  
   - Usuário forneceu: *"Danilo Santos, 91955554444, Vôlei"*.
   - O agente executou duas mutações consecutivas de `criar_reserva`:
     - 17:00 às 18:00: ID `res_mcp_30c9cc30_1791928757`
     - 18:00 às 19:00: ID `res_mcp_9464ee88_1791928772`
   - Ambas foram aprovadas e persistidas com sucesso, bloqueando os horários na agenda do Reservei.

### Teste 2: Consulta e Verificação de Reservas do Cliente (`conversas/transcript_full.jsonl`)

1. **Solicitação do Usuário:**  
   *"gostaria de verificar uma reserva da minha conta no reservei"*
2. **Escolha das Ferramentas pelo Agente:**  
   - Agente solicitou o telefone cadastrado.
   - Usuário informou `91923456789`.
   - Agente chamou `buscar_reservas_cliente(telefone_ou_whatsapp="91923456789")` e não encontrou registros.
3. **Onde o Agente Tropeçou:**  
   - O agente realizou uma segunda chamada redundante com máscara: `(91) 92345-6789`. Embora a função do servidor já faça a normalização interna de dígitos, isso evidenciou cautela do modelo para garantir que a falta de resultados não fosse falha de formatação.
4. **Recuperação e Validação Cruzada:**  
   - Usuário solicitou verificação para `91955554444` (o mesmo número utilizado no Teste 1).
   - O agente chamou `buscar_reservas_cliente("91955554444")`.
   - **Resultado:** A ferramenta localizou instantaneamente os 2 agendamentos de Danilo Santos criados no teste anterior, comprovando a consistência e persistência real ponta a ponta (Leitura -> Escrita -> Leitura).

## 4. Análise de Segurança: A Tríade Letal (Simon Willison)

O conceito da **Tríade Letal** descreve o risco que surge quando um agente possui, na mesma sessão, acesso a:
1. **Dado privado**
2. **Conteúdo não confiável**
3. **Canal de saída**

### Mapeamento no Servidor Reservei

| Perna da Tríade | Presença no Reservei MCP | Análise de Risco |
| :--- | :---: | :--- |
| **Dado Privado** | **SIM** | O servidor tem acesso ao banco de dados do complexo esportivo, lendo nomes de clientes, telefones/WhatsApp e histórico de partidas agendadas. |
| **Conteúdo Não Confiável** | **SIM** | Entradas livres fornecidas por terceiros (nomes, campos de texto, telefones ou payloads vindos do chat do usuário). |
| **Canal de Saída** | **SIM** | A ferramenta `criar_reserva` é um canal de saída com efeito no mundo real: altera a base de dados em nuvem e reserva um espaço físico no complexo esportivo. |

### Medidas de Mitigação Adotadas

1. **Controle de Acesso com Permissão `ask`:**  
   A ferramenta de escrita `criar_reserva` foi configurada obrigatoriamente como `ask` no `.mcp.json`. Qualquer tentativa de mutação exige aprovação humana direta (Human-in-the-Loop), impedindo que um conteúdo malicioso comande reservas fantasmas sem supervisão.
2. **Prevenção Ativa de Double Booking:**  
   O código do servidor consulta a base antes de inserir. Tentativas de agendamento em horários já ocupados são rejeitadas programaticamente, sem depender apenas do bom comportamento do modelo.
3. **Sanitização e Validação Rígida:**  
   Normalização de quadras para identificadores canônicos (`q1`, `q2`, `q3`), validação de datas via regex (`AAAA-MM-DD`), restrição de horários permitidos e higienização de telefones para dígitos numéricos.
4. **Isolamento de Credenciais:**  
   O MCP utiliza a anon key com escopo restrito do Supabase e validação nos cabeçalhos, sem expor chaves administrativas (`service_role`).
